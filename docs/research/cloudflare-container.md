# Cloudflare Container block: Bun, Go and Rust

Reviewed 2026-10-19 after the correction that runtime setups must be installable **blocks targeting Wrangler/Cloudflare Containers**, rather than public standalone starter directories. The feature is one block with three variants because authorization, routing, runtime limits and image deployment are one shared contract. Tests and native manifests travel with the selected implementation.

The service implementations are original. Bun uses Node-compatible streaming APIs with the pinned Bun runtime; Go uses the standard library with bounded streaming and race tests; Rust uses Axum with bounded body collection, a semaphore and a blocking filesystem task that owns its permit through cleanup. All three write only private job directories, bound input to 1 MiB and active jobs to two, prefer verified Linux tmpfs, and fall back to writable ephemeral disk. A UID change alone is not claimed as a sandbox boundary.

The block owns a **dedicated** Wrangler config rather than overwriting the adopter's Worker entrypoint. Its class, binding, image path and explicit build context match. The existing Container class/default scheduling policy matches the portfolio and the pinned SDK. [Current configuration documentation](https://developers.cloudflare.com/containers/configuration/wrangler/) permits the legacy migrations flow but forbids mixing it with the newer exports provisioning flow. [The Container class](https://developers.cloudflare.com/containers/api/container-class/) documents the port, idle lifetime and internet policy used here.

[Filesystem/lifecycle guidance](https://developers.cloudflare.com/containers/faq/) states that default disk is ephemeral and can be discarded across restarts. Neither it nor [local development guidance](https://developers.cloudflare.com/containers/guides/local-dev/) establishes that arbitrary `/tmp` writes are memory-backed or that local `docker run` rights flags map to Wrangler production settings. The latter also documents capabilities differences under the newer Durable Object scheduling policy. The block measures tmpfs instead of assuming it and explicitly distinguishes local smoke flags from Cloudflare behavior.

Verification covers clean installation of the default, both alternate language variants and custom parameters; gateway tests and TypeScript run via `kit verify`. Native package tests check actual HTTP/router handling, byte limits, scratch permissions/cleanup and Go concurrency under the race detector. The explicit repository Docker harness installs each variant into a fresh host, generates its dedicated Wrangler types, typechecks, dry-runs the bundle, builds an amd64 image and invokes the installed Docker smoke. The smoke verifies real hashing, oversized input failure, cleanup, non-root UID, read-only application files and SIGTERM under a bounded tmpfs profile.

An initial test-helper run exposed an inherited `NODE_TEST_CONTEXT` problem: child Node test processes exited successfully without running their tests. Verification now clears that internal environment variable and asserts nonzero child test counts; actual image metadata is also checked. Only reruns after that correction count as Docker evidence.

Independent review also caught per-chunk retention in Worker ingestion and Rust's default temporary-directory mode. The gateway now writes into one fixed byte buffer even for fragmented streams, and Rust explicitly requests mode `0700`; both behaviors have regression tests.

No deployment, production authentication provider, Cloudflare scheduling/egress enforcement, global capacity guarantee, persistent filesystem or production tmpfs guarantee is claimed. Scanner warnings for `child_process` come from the explicit, declared Docker test; installation has no hooks and does not build or run containers automatically.
